# Testing

[한국어](testing.ko.md)

Tests call the code directly. The agent's search tool runs through Strands' own call path (`tool.stream(tool_use, {})`), its MCP client against an in-process fake Gateway (`packages/agent/tests/unit/fake_gateway.py`, behind `httpx.MockTransport`), and whole turns through a real Strands agent with a scripted model. The API runs under FastAPI's `TestClient` with a fake Runtime, the Gateway Lambdas through `lambda_handler(event, context)` with synthetic events and contexts, and the CDK stacks through offline synthesis. No test needs a running MCP server, a model, a live OpenSearch domain or an AWS account. The repository-root `conftest.py` fails any AWS request that escapes its test double, and each Python package keeps an identical copy at its test root, so the guard applies to every test whether pytest runs through `pnpm check` or inside the package.

## Commands

From the repository root, run every gate:

```sh
pnpm check
```

It runs `scripts/check.py`, which syncs and tests `contracts`, `api`, `agent`, `catalog`, `indexer`, `saved-items-lambda`, `gateway-interceptor` and `infra` with placeholder AWS credentials, then runs the scripts tests (the docs checker, the container engine for image builds, release tagging, the AWS guard's copies, preflight's zone, model and Nori checks), the docs check (`scripts/check_docs.py`), the web tests and the production web build.

For focused runs, use one subshell per package so directory changes do not accumulate:

```sh
(cd packages/contracts && uv run --frozen pytest)
(cd packages/api && uv run --frozen pytest tests/test_events.py tests/test_auth.py)
(cd packages/agent && uv run --frozen pytest tests/unit/test_stream_contract.py tests/unit/test_transport.py)
(cd packages/catalog && uv run --frozen pytest)
(cd packages/indexer && uv run --frozen pytest)
(cd packages/mcp-servers/saved-items-lambda && uv run --frozen pytest)
(cd packages/mcp-servers/gateway-interceptor && uv run --frozen pytest)
(cd packages/infra && uv run --frozen pytest tests/test_gateway_identity.py tests/test_operations_stack.py)
python3 -m unittest discover -s scripts/tests
pnpm --filter nordly-web test
```

`python3 scripts/check_docs.py --skip-generated` runs the docs checks without the `docs/generated/` freshness check.

Each package's `pyproject.toml` sets `testpaths = ["tests"]`; the agent's tests are in `tests/unit/`. The two Lambdas, the API and the agent add `pythonpath = [".", "src"]`, so tests import `handler`, `main` or `app` directly; `contracts`, the catalog and the indexer use `pythonpath = ["src"]`, and infra `["."]`.

Each package's copy of the AWS guard is `tests/conftest.py`, identical to the root `conftest.py`. To change the guard, edit the root file and copy it to every package. A new Python package with tests needs the copy in each `testpaths` directory and a place in `PACKAGES` in `scripts/check.py`. `scripts/tests/test_aws_guard.py` fails when a copy is missing or differs from the root's, a test file is outside `testpaths` or defines its own `block_aws_network`, or the packages with tests don't match `PACKAGES`. In packages without botocore, such as the interceptor, the guard does nothing. `packages/agent/tests/unit/test_aws_guard.py` shows it at work: a botocore call with placeholder credentials fails its test before anything is sent.

## Saved-items coverage

`saved-items-lambda/tests/test_handler.py` checks that the handler:

- returns `product.v1` cards for the shopper, drawn from the whole example catalog through the example definition;
- gives each shopper a stable sample, whatever the header's casing, and different shoppers different samples, of a size that depends on the actor ID;
- needs only the standard library and `aria_catalog`;
- raises `PermissionError` for a missing, empty or malformed actor ID, or an actor ID under any other header name;
- respects and caps `limit`;
- rejects unknown tools and arguments;
- logs the agent's trace ID from `x-correlation-id`, and only a well-formed one.

## Interceptor coverage

`gateway-interceptor/tests/test_handler.py`:

- `TestInterceptorContract`: output version `1.0` and an unchanged body. An event without a body, or a body that isn't a single JSON-RPC object (a string, a number or a batch), is denied, since a batch would carry tool calls past the per-call identity check.
- `TestMethods`: `initialize`, `ping`, `tools/list` and notifications pass without an actor; any other method (`resources/read`, `prompts/get` and `sampling/createMessage` among them) gets a method-not-found JSON-RPC error, and a message without a method is raised.
- `TestSettings`: every request is denied while `GATEWAY_AUTH_FLOW` or `AGENT_CLIENT_ID` is missing or the flow is unknown; the agent's own spelling of each flow (`ON_BEHALF_OF_TOKEN_EXCHANGE`, `M2M`) is accepted.
- `TestActorIdentity`: the actor reaches the target on a tool call; tool calls without a well-formed actor ID are denied, and so are differently cased copies of `x-aria-actor-id` with different values; `tools/list` needs no actor; the derivation matches reference values computed with `aria_contracts.identity.actor_id`.
- `TestOnBehalfOf`: the token's `act.sub` must be the agent's client, and the header must name the token's own shopper, tenant claim included; a token without `act` or from another client, an M2M token or no token is denied.
- `TestClientCredentials`: an M2M token's `client_id` must be the agent's client, and its subject isn't compared with the header; a token from another client, without `client_id`, an on-behalf-of token or no token is denied.
- `TestRefusals` and the denial cases above: a refused request is answered with a JSON-RPC error for its own id (`-32003` for a failed check), never forwarded, with the reason only in the log under the line `InterceptorDenials` counts; a string id is echoed; a notification or a boolean id has nothing to answer and is raised, as is an unexpected failure; logs carry header names, never values.
- `TestHeaderForwarding`: `Authorization` is never forwarded, even when allowlisted; the calling trace's ID becomes `x-correlation-id`, from `traceparent` or else `x-amzn-trace-id`, and custom forwarding can't replace it; allowlisted custom headers pass, matched case-insensitively with their casing preserved; other headers are dropped; the custom allowlist cannot replace the checked actor.

## When changing behavior

Update the matching catalog, tool, contract, entrypoint, API, handler, interceptor, stack or web test. Keep the negative cases: unknown tools and methods, unadvertised arguments, missing or mismatched actors and tokens, credentials and ownership. Log event names and error codes are contracts: CloudWatch metric filters count the events, and the web maps each code to Korean copy. The operations, contracts and web tests pin them, so change them together. Do not replace real profile or contract tests with assertions that repeat implementation constants. Local tests do not prove live IAM enforcement, token exchange with your identity provider, model access, sign-in, deployment or recovery. Those need separately authorized acceptance checks; see [live checks after a deploy](#live-checks-after-a-deploy).

## Live checks after a deploy

Unit and synth tests can't show whether AgentCore accepts a configuration or whether a role's permissions are enough. After every deploy to a stage, check:

1. **A conversation.** With `ARIA_API_URL` and a short-lived `ARIA_ACCESS_TOKEN` set, `scripts/smoke.py --invoke` runs a basic turn. It invokes the model and writes Memory events, so it needs authorization.
2. **In the browser:** sign in through managed login and ask for a product (product cards appear, and inline citations show product names). Where the saved-items sample is deployed (the Dev template turns it on; Prod refuses it), ask "내가 저장한 상품 보여줘" (the sample answers through the Gateway).
3. **Catalog search, with `opensearch`,** after indexing the catalog ([operations](operations.md#index-the-catalog)):
   - the task's manifest accepts every product you expect and shows `"promoted": true`;
   - a query that shares no word with a product's text finds it by meaning;
   - a Korean keyword query finds products through Nori, when the definition uses it;
   - a filter-only search, and a range filter if the definition has one, return only matching products;
   - with the embedding model denied to the Runtime role, on a test stage, searches still answer by keyword and the Runtime logs `product_search_embedding_failed`;
   - indexing again as a new version moves the alias, and the manifest names the previous index in `previousIndices`;
   - `product_search_finished`'s `duration_ms`, with and without a query, gives the query embedding's latency.
4. **The Gateway's identity rules,** calling the Gateway directly. Take the URL from the Gateway stack's `GatewayUrl` output, then:
   ```sh
   curl -s -o /dev/null -w '%{http_code}\n' -X POST "$GATEWAY_URL" \
     -H 'Content-Type: application/json' -H 'Accept: application/json, text/event-stream' \
     -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
   ```
   - With no token: 401.
   - With the shopper's own access token, from the web app's sessionStorage, in `Authorization: Bearer`: 403.
   - With an on-behalf-of token: `tools/list` works. Mint one with the exchange request in the [Cognito notes](../references/cognito-token-exchange-notes.md#the-request), reading the agent client's credentials from a file.
5. **Each customer target:**
   - its tools are listed;
   - a call whose `x-aria-actor-id` is the actor ID of the token's shopper succeeds, and the target's logs show its own credential and the actor ID;
   - a call without the header, or with another shopper's actor ID under an on-behalf-of token, is refused without reaching the target: the reply is a JSON-RPC error with code `-32003` (access denied) over HTTP 200, and the interceptor's log has the reason.
6. **When a target answers "An internal error occurred",** look up CloudTrail events from `bedrock-agentcore.amazonaws.com`. An `AccessDenied` there names the resource the Gateway's role is missing ([Gateway notes](../references/agentcore-gateway-notes.md#outbound-credentials)).
7. **The alarms in the operations dashboard are quiet** ([RELIABILITY.md](../RELIABILITY.md)).

Never print tokens or secrets while checking. Decode claims, not tokens.
