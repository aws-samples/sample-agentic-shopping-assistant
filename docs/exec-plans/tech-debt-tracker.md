# Tech-debt tracker

Known gaps, most important first. Add an entry when you find a gap you won't fix now. Remove it, and say so in the change, when it's fixed. [PLANS.md](../PLANS.md) explains how this file fits with execution plans.

## Decisions for the owner

These need a product or architecture decision before anyone builds them.

| # | Gap | Impact | Where | Options |
| --- | --- | --- | --- | --- |
| 1 | A session whose Gateway connection or token mint fails doesn't start; local search fails with it | One unavailable Gateway target, or an IdP outage, takes the whole assistant down | `SessionBuilder.build()`, `packages/agent/src/core/builder.py` | Strands 1.55.1 has the switch: `MCPClient(..., continue_on_error=True)` builds the agent without Gateway tools and logs the failure. Its `connection_failed` flag then stays set for the session's life, so the session must also be rebuilt on a later turn to get the tools back. Decide whether a degraded assistant (search only) is better than an error |
| 2 | The Runtime is invoked on its `DEFAULT` endpoint, which always serves the latest version | No canary or instant rollback; rolling back means redeploying the previous commit ([release](../guides/release.md#roll-back)) | `AgentRuntimeStack`, the API's `AGENT_RUNTIME_ARN` | A named endpoint pinned to a version, promoted after the acceptance checks and repointed to roll back |
| 3 | Gateway tools that change data run without the shopper's confirmation | A prompt-injected or mistaken call can act for the shopper. The shipped tools only read | Agent loop; Gateway targets | Mark write tools in configuration and require a confirmation step (a Strands interrupt plus a confirm card in the web) before the call |
| 4 | A shopper's access token can invoke the Runtime directly, skipping the API | The API's WAF rule, per-IP limit and request checks don't apply to direct calls; the Runtime still verifies the token and the session owner | Runtime `CUSTOM_JWT` authorizer | Accept only a token the API holds at the Runtime, or keep the Runtime reachable only through the API |
| 5 | No per-shopper quota | One account can spend a stage's model budget; WAF limits only per IP | API | Per-principal request and token budgets in the API |
| 6 | In ap-northeast-2, Cohere Embed v4 is offered only through the `global` inference profile | With `opensearch`, the catalog's embedding text and every shopper's query can be processed outside Korea ([integrations](../guides/integrations.md#korean-text-embeddings-and-residency)) | `[catalog.embedding].model`, `packages/catalog/src/aria_catalog/definition.py` | Accept it after a residency review; a geographic profile where Bedrock offers one; or an in-region embedding model, which needs a definition and index change |
| 7 | The API's load balancer admits only `api.allowIpList` | A public storefront needs a public edge | `ApiServiceStack`, `CommonAppStack` | CloudFront with WAF in front of the API before launch; `api.allowPublicIngress` exists for an approved direct exposure |
| 8 | The `product.v1` card fields are fashion-shaped: `gender`, `masterCategory`, `subCategory`, `articleType`, `baseColour`, `season`, `year`, `usage` | Every catalog must map a field to each, so a catalog of anything else shows filler on its cards | `PRODUCT_FIELDS` in `packages/catalog/src/aria_catalog/contract.py`, `[catalog.card]`, the web's `ProductCard.vue` | A generic card contract (`product.v2`) with a name and optional labelled attributes from the definition, rendered as a list |
| 9 | The first turn of every session mints the agent's token and opens the Gateway connection | About 1.4 s more to the first text of a session on Dev | `DownstreamToken`, `MCPClient` start-up | Start the session when the chat panel opens, before the first message |
| 10 | One model serves every turn, with no fallback | When Bedrock fails the configured model, every turn fails. During a Bedrock incident, `gpt-5.6-luna` and seven other GPT models returned HTTP 500 in us-west-2 and ap-northeast-2, through both `global` and `us` profiles, while `gpt-5.4`, `gpt-5.5` and `gpt-6.2` answered | `runtime.modelId`; `_build_model()` in `packages/agent/src/core/builder.py` | A second model the agent switches to on a 5xx, or a runbook step to change `runtime.modelId` through a reviewed deploy |

## Known gaps

| # | Gap | Impact | Where | Suggested fix |
| --- | --- | --- | --- | --- |
| 11 | Guardrail screening of Gateway tool results applies the sensitive-information filters too, and local search results aren't screened at all (the model's guardrail checks only the latest message) | A target's date-like fields can look like card expiry dates and short codes like PINs, so real results may be blocked (`tool_result_blocked`). Catalog text from any provider reaches the model unscreened, so text the customer doesn't control (marketplace listings, reviews) could carry a planted instruction | `GuardrailScreen`, `ToolSafety.after()` in `packages/agent/src/core/safety.py`, `packages/infra/components/guardrail.py` | Check each target's real data with `guardrail.mode = "AUDIT"` before enforcing; if needed, screen tool results with a guardrail that has only the prompt-attack filter. If the catalog carries third-party text (marketplace listings), screen local results too: drop the Gateway-only condition in `ToolSafety.after()` |
| 12 | ApplyGuardrail has per-second text-unit quotas, and screening fails closed | Under load, throttled screening blocks valid tool results (`tool_result_screen_failed`) | `GuardrailScreen` | Request a quota for the expected tool-call rate before launch |
| 13 | A definition change reaches the Runtime in the same deploy as the indexing task, before the catalog is indexed again | Until the new version is promoted, a filter on a new field matches nothing and a new card field drops products. On a stage's first deploy, searches fail until the first load is promoted | Deploy order; `scripts/index_catalog.sh` | Index before the Runtime switches: a staged deploy (the `Opensearch` stack, the load, then `AgentRuntime`) ([operations](../guides/operations.md#change-the-catalog-definition)) |
| 14 | A failed indexing run leaves its index unpromoted, and the indexing task can't delete indexes | Each failed load and every old version keeps its storage until an operator deletes it from inside the VPC; over many loads the domain's disk fills (`SearchDiskLow`) | `packages/indexer/src/aria_indexer/job.py`, `packages/infra/components/catalog_indexer.py` | A reviewed cleanup mode with `es:ESHttpDelete` on `<alias>-*` that refuses the index behind the alias |
| 15 | The catalog definition reaches the Runtime and the indexing task in environment values | AgentCore Runtime's CloudFormation resource takes at most 2,048 characters a value, and the definition is split across at most 8 of them, so a definition over 16 KB of JSON, such as many filters with long value lists, fails synth; the example takes about 2,400 characters, in two values | `checked_environment()` in `packages/infra/stacks/agent_runtime_stack.py` | Ship the definition in the images, or read it from S3 or SSM at start-up |
| 16 | Managed login is unbranded | The sign-in step doesn't look like the NORDLY storefront; the web asks for Korean (`lang=ko`) | `AuthStack` (`CfnManagedLoginBranding`) | Brand managed login |
| 17 | The `TOKEN_EXCHANGE` grant for Gateway targets isn't exposed in configuration | A customer API can't receive a token it can verify; it must trust `x-aria-actor-id` | `ToolTargetConfig.grant_type`, `GatewayStack._outbound_credential()` | Add `TOKEN_EXCHANGE`, passing `subject_token_type` through `customParameters` |
| 18 | MCP targets with API keys, and Cedar policies in `LOG_ONLY`, haven't been run live | Unverified paths; see [quality score](../QUALITY_SCORE.md) | — | Run them on a stage before relying on them |
| 19 | No synthetic canary | An outage between shopper turns goes unnoticed until someone chats | `OperationsStack` | A scheduled sign-in-and-ask check with its own alarm |
| 20 | No one-step kill switch for tools | Turning off a misbehaving Gateway tool takes a configuration change and a deploy | `gateway.targets[].allowedTools`, Cedar | Document the fastest path (a Cedar `forbid` in `ENFORCE`), or add a runtime flag |
| 21 | The MCP start-up timeout (10 s) doesn't cut off a hung `initialize` | A Gateway that accepts the connection and never answers holds a session build for the 30 s read timeout | `SessionBuilder._build_mcp_client()` | Bound the whole build with the request deadline |
| 22 | The Memory namespace format is written in three places | A change in one breaks retrieval or deletion silently | `packages/agent/src/core/memory.py`, `packages/api`, `packages/infra` | Move it into `packages/contracts` with the other shared identity rules |
| 23 | Custom headers to Gateway targets are fixed when the session is built; local tools get each turn's values | A header that changes mid-session (a locale switch) reaches Gateway targets stale | `SessionBuilder._build_mcp_client()` | Rebuild the MCP client when forwarded headers change |
| 24 | The saved-items Lambda's asset bundles all of `aria_catalog` | Any catalog change redeploys the sample Lambda | `GatewayStack._create_saved_items_target()` | Bundle only the modules it imports |
| 25 | The catalog's Secrets Manager client uses botocore's default timeouts | A slow Secrets Manager can stall an HTTP-catalog search past its 10 s budget | `packages/catalog/src/aria_catalog/providers.py` | Give the client short connect and read timeouts |
| 26 | The web app has no component tests | Vue templates are checked only by the build and by hand | `packages/web` | Add `@vue/test-utils` with a DOM environment |
| 27 | CDK cross-stack references default to "strong" exports | Removing a referenced resource needs a staged deploy | `packages/infra/app.py` | Adopt weak references when CDK's `defaultCrossStackReferences` is stable, or keep referencing by name |
| 28 | Constants shared across packages are copied by hand: the `___` tool separator, the 8,000-character prompt limit, `x-aria-actor-id`, `product.v1` | A change in one package silently diverges from the others | agent, API, infra, web, the Lambdas | Move them into `aria_contracts`, and pin the stdlib-only Lambda copies with tests |
| 29 | The web's error-code copy is a hand copy of the contract's codes | A new code gets generic copy in the web | `packages/web/app/utils/errors.ts` | A web test that reads the contract's `ERROR_CODES` and checks every code has copy |
